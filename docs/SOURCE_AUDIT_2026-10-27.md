## สิ่งที่แก้เบื้องต้นใน Code.gs
1. เพิ่ม `requireAdmin_()` และเรียกก่อน `fixFormulas()` และ `checkSetup()`
2. ป้องกันปริมาณสินค้าที่ไม่ใช่จำนวนจำกัด (NaN/Infinity) ในรายการรับจ่าย ใบเบิก และใบเสนอราคา
3. เปลี่ยน `deleteMovementCore_` ให้ทำเครื่องหมาย `ยกเลิก-รับเข้า` / `ยกเลิก-จ่ายออก` ในประเภทการเคลื่อนไหว พร้อมโน้ต audit ในเซลล์ แทนการล้างข้อมูลแถวเดิม
4. ช่วยป้องกันยอดรวมใบเสนอราคาที่ไม่ใช่ตัวเลขจำกัด

## ข้อควรระวัง: ยังไม่พร้อม Deploy
- การยกเลิกทั้งใบอัปเดตหลายเซลล์ และยังไม่ใช่ธุรกรรมแบบ atomic — หาก Apps Script ล้มระหว่างทาง อาจเกิดการยกเลิกบางส่วน
- ระบบจะไม่นับแถวประเภท `ยกเลิก-*` ใน `readMv_` และสูตร `SUMIFS` ที่นับเฉพาะ `รับเข้า/จ่ายออก` เท่านั้น ต้องตรวจสูตรเดิมทุกส่วนก่อนใช้จริง
- `fixFormulas()` มีการเขียนสูตรและย้าย movement จริง ห้ามรันโดยไม่สำรองและตรวจรายการ
- `PDF_SHARE_ANYONE=true` ทำให้ PDF แชร์ได้กับทุกคนที่มีลิงก์ ต้องทบทวนนโยบายการเข้าถึง
- ยังไม่ได้ตรวจการเชื่อม **ออร์เดอร์และใบขาย / รายการขาย** ซึ่งมีแท็บใน Google Sheets แต่ไม่พบโค้ดการเชื่อมในไฟล์เซิร์ฟเวอร์นี้
- `Session.getActiveUser().getEmail()` อาจไม่คืนค่าใน deployment บางรูปแบบ ต้องทดสอบสิทธิ์ตามวิธี Deploy จริง
- แพตช์ยังไม่ได้ผ่าน integration tests กับ Google Apps Script/Google Sheets; ผ่านแค่ syntax check และ unit tests แบบจำลอง
- ฟังก์ชัน `savePdf()` ยังต้องเพิ่มการตรวจเนื้อหา PDF, ขนาดไฟล์, สิทธิ์ และการเก็บเวอร์ชันก่อน Deploy
- แพตช์นี้ยังไม่รวมการป้องกัน duplicate request/issue แบบครบทุกเส้นทาง หรือการกู้คืน transactional failures

## แผนถัดไป
1. ใช้สำเนา Google Sheets (staging) เพื่อทดสอบผลของการลบรายการและคืนสต๊อก
2. พัฒนา movement reversal แบบ append-only ที่ใช้ transaction ID, operation ID, lock, และ retry อย่างปลอดภัย (ไม่เปลี่ยน Type เพื่อยกเลิก)
3. เชื่อม flow ออร์เดอร์ -> ใบขาย -> ส่งมอบหนึ่งครั้ง โดยไม่สร้างชีตออร์เดอร์ใหม่
4. ตรวจสิทธิ์รายฟังก์ชัน และปรับ PDF/private access
5. ตรวจ UI และ deploy เฉพาะเวอร์ชันทดสอบก่อน production
