# บันทึกตรวจสอบโครงสร้างฐานข้อมูล (อ่านอย่างเดียว)

วันที่ตรวจ: 2026-10-27 (ประเทศไทย)

## สถานะหลักฐาน

- **ยืนยันได้:** Google Drive ที่เชื่อมต่อมองเห็นไฟล์ **สต๊อกสินค้า LED** ซึ่งมี 9 แท็บ และไฟล์ชื่อ **สต๊อกสินค้า LED — สำรองก่อนเพิ่มออร์เดอร์และใบขาย 2026-10-16** ซึ่งมี 7 แท็บ
- **ยังไม่ยืนยัน:** เว็บแอป Google Apps Script ที่ผู้ใช้ส่งลิงก์มาเชื่อมกับสเปรดชีตใดจริง (Apps Script source / code files ยังไม่ถูกอ่านจาก Editor)
- **ไม่มีการแก้ไขข้อมูล:** ตรวจ metadata และช่วงเซลล์หัวตารางแบบ read-only เท่านั้น
- **ไม่บันทึกใน GitHub:** แถวธุรกรรม, ข้อมูลผู้ใช้, ข้อมูลลูกค้า, ยอดคงเหลือ และรายการสินค้าเฉพาะแถว

## หลักการออกแบบก่อนแก้

1. ห้ามสร้างตาราง 'ออร์เดอร์และใบขาย' และ 'รายการขาย' เพิ่มซ้ำ
2. แยก immutable key (ReqID/OrderID/MovementID/LineID/SaleLineID) จากเลขเอกสารที่ผู้ใช้แก้ได้
3. ตรวจโค้ดเดิมว่าเหตุการณ์ใดบันทึก movement จริง ก่อนเขียน 'ตัดสต๊อกครั้งเดียว'
4. ห้ามลบธุรกรรมสต๊อกตรง ๆ โดยไม่มีรายการย้อนกลับหรือ audit trail
5. ป้องกันการเขียนซ้ำด้วย key การทำรายการ + LockService เมื่อไปเชื่อม Apps Script
6. ทดสอบสถานะ: จอง -> อนุมัติ -> จ่าย/ส่งมอบ -> ยกเลิก/คืนยอด; รวมกรณีเชื่อมใบขายกับใบเบิก
7. ห้ามคัดลอกแถวลูกค้า/ข้อมูลธุรกิจจริงเข้าชุดทดสอบ GitHub

## ขั้นตอนที่ยังติดขัด

ลิงก์ Apps Script Editor ที่ได้รับไม่สามารถอ่านไฟล์ `.gs` / `.html` ผ่านเครื่องมือ Google Drive ปัจจุบันได้ (Drive metadata สำหรับ Project ID ไม่พบไฟล์). ต้องได้รับไฟล์ซอร์สโค้ดจาก Editor, เชื่อม Apps Script API/`clasp` หรือใช้ Browser ใน Work mode ที่เข้าถึงบัญชีได้ ก่อนทำ code review จริง

## ตรวจหลังรับโค้ด

- สคริปต์ผูกกับ Spreadsheet ID ใด และใช้ getActiveSpreadsheet / openById อย่างไร
- ชื่อฟังก์ชัน doGet, ฝั่ง server ที่เรียกผ่าน google.script.run, การทำ LockService
- การอัปเดต คลังสินค้า.จ่ายออก/รับเข้า/คงเหลือ และ movement log
- การแก้/ยกเลิกใบเบิกและการจัดการคำสั่งขายซ้ำ
- PDF และ permissions แบบ public/user/admin

> เอกสารนี้เป็น schema audit เท่านั้น ไม่ใช่ผลยืนยันความถูกต้องของระบบ production
